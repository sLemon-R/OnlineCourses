# Стандарт кодування проєкту OnlineCourses

## 1. Загальні положення

1.1. Стандарт діє для всього коду в репозиторії OnlineCourses (бібліотека OnlineCourses.Core, консольний застосунок OnlineCourses.App і тести, коли вони з'являться).

1.2. Мова коду — C# 12, платформа .NET 8. Імена типів, членів і змінних пишуться англійською. Коментарі, XML-документація, повідомлення комітів і тексти для користувача — українською.

1.3. Якщо пункт стандарту закріплено в `.editorconfig` або аналізатором, головним вважається машинне правило. Розбіжність між цим документом і `.editorconfig` — дефект документа, його треба виправити.

1.4. Код, що потрапляє в гілку `main`, збирається командою `dotnet build` без жодного попередження і проходить `dotnet format --verify-no-changes`.

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
|---|---|---|---|
| Клас, запис | PascalCase, іменник | `EnrollmentLine` | `enrollmentline` |
| Інтерфейс | I + PascalCase | `IEnrollmentRepository` | `Repository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calc` |
| Властивість | PascalCase, іменник | `UnitPrice` | `GetUnitPrice` |
| Приватне поле | _ + camelCase | `_lines` | `m_Lines` |
| Локальна змінна | camelCase | `totalAmount` | `ta` |
| Параметр методу | camelCase | `courseCode` | `CourseCode` |
| Константа | PascalCase | `MaxLineCount` | `MAX_LINES` |
| Перелічення | PascalCase, однина | `EnrollmentStatus` | `EnrollmentStatuses` |
| Булева властивість | префікс Is/Has/Can | `IsReturning` | `Returning` |

Додаткові правила:

2.1. Скорочення в іменах заборонені, крім загальновживаних (`Id`, `Url`, `Json`).

2.2. Ім'я файлу збігається з іменем єдиного публічного типу в ньому (`Enrollment.cs` → `Enrollment`).

2.3. Метод, що повертає `bool` і не кидає винятку в разі невдачі, має префікс `Try` (`TryChangeStatus`).

## 3. Форматування

3.1. Відступ — 4 пробіли; табуляція заборонена. Для `.csproj`, `.props`, `.json`, `.yml` — 2 пробіли.

3.2. Довжина рядка — не більше ніж 100 символів.

3.3. Фігурні дужки — стиль Allman (кожна дужка на окремому рядку), обов'язкові навіть для однієї інструкції в тілі `if`, `for`, `foreach`, `while`.

3.4. Між членами класу — рівно один порожній рядок.

3.5. Директиви `using` — на початку файлу, поза простором імен, системні (`System.*`) перші, невживані видаляються.

3.6. Простір імен — файлового рівня (`namespace OnlineCourses.Core.Domain;`).

3.7. Один оператор — один рядок. Запис `a = 1; b = 2;` в одному рядку заборонений.

3.8. Файл закінчується порожнім рядком, пробілів у кінці рядків немає.

## 4. Коментарі та документація

4.1. Коментар пояснює, чому код написано саме так, а не що він робить.

4.2. Закоментований код не зберігається: для старих версій є історія Git.

4.3. Усі публічні типи й члени бібліотеки OnlineCourses.Core мають XML-документацію `<summary>` (обов'язково з ЛР № 4).

4.4. TODO-коментар має формат `// TODO(прізвище): що зробити` і не живе довше за одну лабораторну роботу.

Приклад «погано — добре»:

```csharp
// погано: коментар переказує код
// збільшуємо лічильник на одиницю
count = count + 1;

// добре: коментар пояснює причину рішення
// платформа рахує тривалість курсу в повних годинах, тому округлюємо вгору
hours = Math.Ceiling(rawHours);
```

## 5. Структура проєкту

5.1. Рішення складається з двох проєктів: `OnlineCourses.Core` (логіка предметної області) і `OnlineCourses.App` (введення й виведення). З ЛР № 7 додається проєкт тестів.

5.2. `OnlineCourses.Core` не звертається до `Console` і не читає файли напряму — тільки через інтерфейси.

5.3. Доменні сутності лежать у теці `Domain`, сервіси — у теці `Services`.

5.4. Гроші — тип `decimal`, дати — `DateOnly` або `DateTimeOffset`.

## 6. Правила комітів

6.1. Повідомлення — за Conventional Commits: `тип: коротка суть` (`feat`, `fix`, `docs`, `chore`, `style`, `refactor`, `test`).

6.2. Суть пишеться українською, у формі «що зроблено», не довше за 72 символи.

6.3. Один коміт — одна завершена зміна; після кожного коміту проєкт збирається.

6.4. Теки `bin` і `obj` до репозиторію не потрапляють (відсікає `.gitignore`).
